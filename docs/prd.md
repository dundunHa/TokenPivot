# TokenPivot 产品需求文档

> 版本：v0.3
> 日期：2026-10-27
> 状态：视觉与技术路线已确认，评审修正已纳入；剩余接口与性能细节另列。本文不是实施计划，不授权开始实现。
> 技术文档：[架构](architecture.md) · [数据模型](data-model.md)。

## 1. 产品定位与目标

TokenPivot 是一个模型 Token 用量追踪仪表盘，通过 Agent 工具插件上报使用数据，按供应商（Provider）、模型（Model）、项目（Project）和时间分析消耗。

核心问题：

1. 今天、每小时、每分钟消耗了多少 Token？
2. 哪个供应商、模型、项目贡献了主要消耗？
3. 最近一分钟的消耗速率是多少？
4. 用量峰值发生在什么时候，来自哪些项目和模型？

### 已确认约束

- 后端使用 Go。
- 前端使用 TypeScript、React、shadcn/ui、Tailwind CSS。
- 黑色主题，追求有辨识度、精致且酷炫的数据仪表盘。
- 支持 Provider、Model、Project 维度，以及分钟、小时、天的统计。
- 速率指 Token 消耗速率，不是单次回答的生成速度。
- 服务端只定义统一采集接口，不实现各 Agent 平台内部的数据采集逻辑。
- 首批数据采集插件面向 DSH 与 PI，作为独立交付项开发。
- 从开始考虑多租户，采用用户与工作空间划分。

## 2. 用户与部署场景

同一代码库和核心服务支持官方云端 SaaS 与用户自托管，功能不分叉。前端为独立工程：开发独立运行，自托管可内嵌构建产物，云端可独立静态托管；首版浏览器与 API 通过同源入口访问。

### 已确认的身份与数据归属

- 用户表示使用者；工作空间表示数据归属范围，也就是租户。
- 一个用户最终可以加入多个工作空间；本期只交付个人空间，多空间属于后续任务。
- 个人使用对应个人工作空间；团队使用对应共享工作空间（团队空间属后续任务，本期不交付）。
- 项目、插件接入凭证、用量数据归属工作空间。
- 服务端根据接入凭证确定上报归属，不信任客户端任意指定的用户或租户 ID。
- 查询、汇总、明细与后续导出均限制在用户有权访问的工作空间内。

已确认：账号与工作空间隔离；owner 管理项目和凭证，member 查看使用。浏览器使用同源会话 Cookie，写请求校验 Origin。初期不提供发邮件能力：账号密码直接注册，不以邮箱验证作为登录前置，注册成功即创建 30 天滑动会话；SMTP 邮箱验证、邀请和密码重置归 T-018。公开注册**默认关闭**，由部署环境变量 `TOKENPIVOT_REGISTRATION_OPEN` 控制：启动时读取一次，未设置等同 `false`，只接受精确的 `true`/`false`。关闭时仍允许空库的首个用户注册（该用户同时获得自己的 `Personal` 个人空间），此后所有注册一律 `403 REGISTRATION_CLOSED`，也不提供查询注册是否开放的端点；因此「支持注册」不等于「所有部署默认无限制开放注册」，云端需要公开注册时由部署方显式打开，自托管同样由这个开关决定。本期所有工作空间均为个人空间：注册时在同一事务内创建展示名为 `Personal` 的个人空间并写入 owner 成员关系，用户既是该空间的唯一成员也是 owner，因此「首次 owner 初始化」已不再是待确认事项；团队空间、成员管理、邀请交互与空间切换全部属于后续任务，本期不交付。

已确认（T-054）：owner 可创建、修改、归档空间内的项目与数据来源，member 只读，非成员无权限。删除即**归档**：保留历史事件、分钟聚合、来源与凭证记录，不可恢复，归档后的项目键、来源标识仍被占用，不能删除后用同键重建；归档来源会同时撤销其有效凭证并拒绝新的签发/轮换，归档前已认证的采集请求允许完成；项目归档不影响采集接收。

## 3. 系统职责边界

### 3.1 TokenPivot 服务端

- 定义统一数据采集接口与格式版本。
- 负责接入认证、租户隔离、输入校验、去重、存储和统计。
- 提供仪表盘所需的筛选、分组、时间聚合与明细查询能力。
- 展示已接入数据源的上报状态和数据完整性。
- 不解析 DSH、PI 的内部日志，不包含平台专用采集逻辑。
- 不代理模型调用，不承担模型路由、供应商切换或请求转发。

### 3.2 DSH 与 PI 插件

- 采集所在平台的模型用量及项目归属。
- 将平台数据转换为统一上报格式。
- 负责失败重试、断网补报。
- 无法获取的字段标为缺失，不用零代替。
- 不重复上报为新的用量事件；真实的新调用不能误认为重复传输。

各平台可获取的字段、采集入口与生命周期尚未核实。本文不假定两个平台具备相同的能力。

### 3.3 隐私默认

不收集 Prompt、回答正文、本地完整项目路径或供应商密钥。项目使用可公开的标识与名称，不以绝对文件路径作为展示身份。

已确认：插件实例 source 身份独立于凭证，轮换不改变 source，撤销凭证不清除防重依据。TODO（待确认）：插件项目及实例稳定标识生成、不同插件实例的项目合并规则。

## 4. 典型使用流程

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 日常查看 | 打开今天的总览 | 看到总量、输入输出构成、小时趋势 |
| 找主要消耗来源 | 按项目、模型或供应商排序 | 找到主要消耗来源及占比 |
| 观察近期活动 | 选择最近一小时、分钟粒度 | 看到分钟变化与滚动一分钟消耗 |
| 排查峰值 | 选择趋势中的峰值时间段 | 查看对应来源及可用的请求明细 |
| 查看采集情况 | 打开数据源状态 | 区分正常、延迟、离线及数据缺失 |
| 查看工作空间范围（本期） | 打开总览 | 只显示当前个人空间内有权访问的数据 |

## 5. 首版功能范围

除明确标为已确认的核心能力外，下列交互细节为首版建议，需在实施计划前确认。

### 5.1 全局筛选

- Provider、Model、Project 支持组合筛选与多选。
- 时间范围建议包括最近一小时、今天、昨天、最近七天、自定义。
- 时间粒度支持分钟、小时、天。
- 支持按 Provider、Model 或 Project 分组。
- 显示当前工作空间、时区、统计范围与最后更新时间。
- 建议将非敏感筛选条件保存在 URL，刷新或分享后可恢复；分享不绕过权限。
- 长时间范围需要调整粒度时明确提示，不静默改变。

### 5.2 总览仪表盘

顶部指标：所选时段总 Token、输入 Token、输出 Token、请求数、最近 60 秒用量。

主要区域：

1. 用量趋势主图：输入、输出及总量随时间的变化。
2. 来源排名：按项目、模型、供应商切换并排序。
3. 用量构成：显示主要来源占比，长尾可归为“其他”并展开。
4. 请求明细：仅在上报数据支持请求级明细时提供。
5. 数据状态：最后接收时间、覆盖来源、缺失或延迟提示。

建议点击排名项直接筛选，框选趋势时间段联动明细。不能将部分插件的数据呈现为用户所有账户的完整使用量。

### 5.3 维度详情

复用分析能力提供项目、模型与供应商详情：总量、趋势和其他维度的分布。

建议同名模型经不同供应商调用时分别统计；模型系列合并及别名规则为 TODO（待确认）。

### 5.4 请求明细

建议字段：请求时间、Provider、Model、Project、输入/输出/总 Token、状态、耗时、来源、用量完整性。

状态与耗时仅在来源能够提供时显示。若来源只有汇总数据，不生成虚构请求，不把小时数据拆成伪造的分钟数据。

### 5.5 数据源状态

显示来源平台、插件实例、插件版本、最近成功接收时间、数据完整性与错误状态。

“没有新用量”和“插件离线”不能仅根据没有事件等同判断。具体状态检测方式为 TODO（待确认），不得在未实现检测时宣称实时在线。

## 6. 统一采集接口的产品要求

本节定义信息需求，不锁定接口路径、字段名、传输协议或数据库结构。

| 类别 | 必须解决的问题 |
| --- | --- |
| 事件标识 | 同一事件重传不重复计数；区分真实新调用与重复传输 |
| 来源 | 区分 DSH、PI 和插件实例 |
| 租户归属 | 根据接入凭证确定工作空间，不由上报载荷任意选择 |
| 项目归属 | 能区分项目；无法归属时进入“未归属”，不能丢弃 |
| 模型信息 | Provider 与 Model 分开记录 |
| 用量 | 输入、输出及可获取的缓存明细；明确总量与子集关系 |
| 时间 | 区分用量发生时间与服务端接收时间，支持补报历史数据 |
| 完整性 | 区分真实零值、缺失和估算数据 |
| 格式版本 | 能识别插件与服务端的格式兼容范围 |

已确认：批量逐项结果，每项独立事务，仅接收请求完成后的最终用量，不允许静默修正。身份为工作空间、稳定插件实例、来源事件 ID；同身份同规范化内容为 duplicate，不同内容为 conflict。

用户选择 A：仅接受发生时间距服务端当前时间 180 天以内的补报；180 天为 180×24 小时。明细与防重依据按首次接收时间保存 180 天，重传不续期。过期事件返回 expired，先于查重，不再承诺 duplicate/conflict。客户端不得复用 ID 或修改时间绕过窗口。

## 7. 指标口径

下列为建议口径，需在接口设计前确认并用样例验证。

| 指标 | 定义 |
| --- | --- |
| 输入 Token | 归一化后的输入总量；缓存明细若为子集，不重复累加 |
| 输出 Token | 归一化后的输出总量；推理明细若为子集，不重复累加 |
| 总 Token | 可归一化的输入与输出之和；来源数据无法对应时显式标记差异 |
| 每分钟用量 | 每个自然分钟内归属事件的 Token 总量 |
| 当前消耗速率 | 最近滚动 60 秒发生的 Token 用量，单位 tokens/min |
| 每小时/每日用量 | 按选定时区的自然小时或自然日聚合 |
| 请求数 | 实际调用次数；真实重试是新调用，上报重传不是新调用 |

### 时间归属建议

- 首版将请求最终用量计入完成时刻所在时段，不按流式分片拆分。
- 长请求在完成时可能形成峰值，界面需要说明。
- 历史补报回填发生时段，不算作接收时刻的新消耗。
- 当前消耗速率基于已收到的数据计算，必须同时呈现新鲜度；延迟数据不能被描述为完整实时数据。
- 同一筛选范围、时区及数据状态下，不同时间粒度的汇总结果应一致。

### 禁止混淆

- 消耗速率不等于生成速度。
- Token 用量不等于账单金额。
- 缺失用量不等于零用量。
- 失败请求不一定没有消耗。
- 缓存和推理明细可能是子集，不能盲目相加。
- 只有汇总用量时不能推算并展示真实请求数。

## 9. 首版建议不包含

- 模型请求代理、路由和自动切换供应商。
- Prompt 与回复正文管理。
- 单请求生成速度分析。
- 精确账单核算、充值、支付与商业套餐。
- 自动异常检测、预算通知与告警。
- 原生移动客户端。

同代码库云端/自托管支持属于首版。最小 owner/member 成员管理（成员列表、邀请、移除、角色变更）与多空间切换**不在本期交付**：本期每个用户只有一个自动创建的个人空间，owner 关系随之写入，因此没有可切换的目标也没有可管理的成员；这些能力排队等后续任务。高级团队管理、CSV 导出、费用估算、自定义保留管理界面仍为 TODO（待确认）；不因管理界面后置而推迟租户隔离。

## 10. 验收标准

1. Provider、Model、Project 组合筛选同时作用于指标、图表与明细。
2. 相同时间范围与口径下，分钟、小时、天汇总结果一致；未完成时间段明确标记。
3. 相同事件重复上报不重复计数，真实新调用不会被误去重。
4. 零值、缺失、估算、延迟与无数据状态可区分。
5. 跨午夜统计遵从所选时区。
6. 缓存、推理明细不重复累计。
7. 历史补报回填正确时段，不制造接收时刻的虚假峰值。
8. 任何采集、查询和统计路径都不能跨越工作空间权限边界。
9. 出现多工作空间后（本期每个用户只有一个个人空间，无切换入口），切换不得残留前一个工作空间的可见数据。
10. 无法确认来源在线时，不宣称“实时正常”。
11. 数据源不支持的明细和指标显示不可用，而不是伪造或填零。
12. 默认采集内容不含 Prompt、回复正文、完整本地路径和供应商密钥。

建议时效目标：可实时上报的数据在服务端接收后 10 秒内出现在页面；此目标尚待确认，来源自身延迟单独显示。

已确认：每日约 10 万事件为规划规模；明细按首次接收时间保留 180 天，UTC 分钟聚合按发生分钟保留 13 个日历月，不做冷归档。仅在明细完整覆盖范围内可重建，更老汇总需备份恢复。历史查询采用分钟对齐范围并显示实际范围，滚动 60 秒独立按精确时间计算；当前未完成分钟明确标记。

补充验收：过期补报与清理边界、轮换后重传、缺失/估算聚合、重建中断和旧汇总不变、同源两种部署、非法写请求来源均需覆盖；空间切换慢响应等出现多空间切换界面时（后续任务）再补。

## 11. 后续交付边界与待确认项

后续工作分为服务端与仪表盘、DSH 插件、PI 插件三个交付范围。本文不规定其代码仓库位置或实施顺序。

3. 细化已确认的部署、身份认证与最小成员管理流程。
4. 在已确认的数据规模与保留期下确定性能目标和压测环境。
5. 以已确认的 F 原型为基准，确定正式前端的组件范围、设计变量与响应式策略。
