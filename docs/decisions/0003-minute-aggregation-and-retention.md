# ADR-0003：分钟聚合与180天补报窗口

状态：已确认；用户选择 A。关联 T-001。

## 决策

- 原始事件和其中的防重依据按首次received_at保留180天；重传不续期。
- 接收窗口为 `[服务端时间-180×24小时, 服务端时间]`。超期永久拒绝expired，且先于查重，不永久保存身份摘要。不承诺识别超出期限后被改时间、复用ID的内容。
- UTC分钟统计按bucket_start保留13个日历月，按完整分钟清理；统计按occurred_at而非received_at。
- 只有首次接受才同步增加分钟统计。小时/天从分钟汇总计算；滚动60秒独立查原始事件。
- 历史统计范围以分钟对齐；秒级范围不静默近似。当前未完成分钟单独标记。统一左闭右开区间。

## 备选与取舍

A：限定180天补报，使用明细保存防重依据，规则简单。B：支持13个月补报并独立长期保存身份摘要，增加存储与清理。用户选A。单纯明细查询无法提供清理后的13个月统计，因此保留分钟聚合；不维护三套独立聚合流水线。

## 重建边界

按接收时间保留可能留下部分更老发生时段明细，不代表这些时段完整。仅重建明细完整覆盖的分钟范围（正常保留策略下最近180天并结合服务起点/清理记录）；更老汇总保持不动。维护窗口暂停摄入和清理、事务替换；失败回滚，上报得到可重试错误。更老历史靠数据库备份恢复，不能承诺全部可重算。

## 后果与改变代价

超过窗口的合法新补报也会拒绝；界面须提示而不是无限重试。未来延长窗口需要调整防重依据保留，已经清理的数据无法恢复。缩短明细保留会破坏当前防重关系，不能作为独立开关任意改动。同步聚合未达性能目标时再评估异步。

验收：时间边界、清理前后重传、迟到回填、未完成桶、DST、缺失质量、重建中断与旧汇总不变。详见 [架构](../architecture.md) 与 [数据模型](../data-model.md)。
