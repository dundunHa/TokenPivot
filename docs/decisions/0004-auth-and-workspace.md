# ADR-0004：账号、工作空间与同源会话

状态：已确认，关联 T-001。

## 决策

用户可加入多个workspace；owner负责管理，member查看使用。每个浏览器业务请求检查目标workspace成员资格；插件凭证固定workspace/source，不相信客户端租户声明。所有查询与唯一约束限定workspace，首版不启用RLS，应用层仍须有越权验收。

浏览器使用主机范围会话Cookie，生产Secure、HttpOnly、SameSite=Lax；写请求校验Origin，拒绝不匹配/缺失来源。开发经Vite代理，生产经同源入口；独立静态托管不等于跨源API。插件端点独立使用凭证，不回退Cookie。凭证保存摘要，轮换不改变source。

**2026-10-28 用户决策（取代前文"开放注册使用邮箱验证，SMTP提供验证、邀请和重置"的旧口径）**：初期不提供发邮件能力，账号密码直接注册，**不以邮箱验证作为登录前置**；首版不依赖 SMTP。密码用 Argon2id 编码存储，会话为 `tps_` 前缀的不透明令牌，数据库只存 SHA-256 摘要，30 天滑动过期、无绝对截止。注册成功直接创建首个会话，不要求再次输入密码。T-016 实现上述内容；T-017 只处理注册开关，以及把个人空间初始化编排进 T-016 现有注册事务；T-018 若恢复 SMTP、邮箱验证与密码重置，须另行决定 `email_verified_at` 与存量未验证用户的规则。自托管仍可关闭公开注册。首个 owner 由注册创建个人空间时一并写入（见下条 T-019 决策），不再是未决事项。保护最后一位 owner，邀请/重置等一次性令牌必须在实现时定义到期时间且只消费一次。

注册与登录都必须限流；直接注册必然可能通过"邮箱已占用"结果探测账号存在，本决策不宣称注册可完全防枚举。

**2026-10-28 个人空间限定决策（T-019）**：本期所有工作空间都是个人空间。注册为每个新用户创建唯一初始个人空间（展示名固定为 `Personal`）并写入其 `owner` 成员关系；不增加 personal/team 类型字段，不实现团队空间、邀请/接受/移除、角色变更、跨空间迁移、空间删除或重命名，也不新增工作空间 HTTP API 或多空间切换能力。个人空间创建与用户、首个会话在同一数据库事务内完成，任一步失败整体回滚；同一用户的重复或并发创建只产生一个空间和一条 owner 成员关系（锁 `users` 行后先查已建 owner 空间，未找到才插入，且事务须为 READ COMMITTED）。成员角色查询只有 `(user_id, workspace_id) → owner/member` 一个入口，非成员返回 `found=false`，未知角色与数据库故障返回错误，不得伪装成非成员。用户后来加入其他空间时，其个人历史仍归原个人空间，**不自动复制、移动或共享**；未来团队空间与成员管理由 T-020 另行规划，届时须先重审「按用户查 owner 空间」这条规则再复用于多空间。

前端缓存键包含workspace，切换时隔离旧数据、取消旧请求，不允许迟到响应覆盖新空间。

**2026-10-28 注册开关决策（T-017）**：公开注册默认**关闭**，由部署环境变量 `TOKENPIVOT_REGISTRATION_OPEN` 控制，启动时读取一次、不做热加载；未设置等同 `false`，只接受精确的 `true`/`false`，其他写法使服务启动失败且错误不回显输入值。云端需要公开注册时显式设为 `true`。关闭时仍允许**空库的首个用户**注册，该用户同时获得 `Personal` 个人空间和 `owner` 成员关系；此后所有注册一律拒绝，直到部署方显式打开开关。这不推翻前文“直接注册、注册即建个人空间”的决策，只是给公开注册加一道默认关闭的部署开关。

拒绝用专用哨兵错误映射为 HTTP **403 + `REGISTRATION_CLOSED`**（固定 message `registration is closed`），响应保持 `Cache-Control: no-store`、不下发 Cookie、不写库；不提供查询注册是否开放的端点。因为准入判断先于用户写入和邮箱唯一冲突，已占用邮箱与从未注册的邮箱得到完全相同的响应，关闭模式不会额外泄露账号是否存在；开放模式仍是 `409 EMAIL_UNAVAILABLE`，前文“注册不能完全防枚举”的结论继续只适用于开放模式。

**空库并发的处理方式**：空库判定与首个用户写入放在同一数据库事务内，事务显式使用 `READ COMMITTED`，先取事务级排他 advisory lock（固定双整数键 `17017, 1`，是包内常量、不是配置）再单独查询 `users` 是否为空；锁持有到该事务提交或回滚。阻塞版锁使后到请求等待前者结束：前者回滚则后者仍看到空库并可以成为首个用户，前者提交则后者必须看到已有用户并返回 `REGISTRATION_CLOSED`。同一时刻只有一个请求能做空库判定，因此空库上的并发首注册只有一个成功。开放模式跳过锁与空库查询，相同邮箱的并发注册由 `uk_users_email` 仲裁。获取锁或查询失败按安全数据库错误上报，不得伪装成“注册已关闭”或“空库”。

一个账号的四部分写入（`users` 行、`Personal` 个人空间、`owner` 成员关系、首个 `sessions` 行）在同一事务内按固定顺序完成，任一步失败整体回滚；Argon2id 与令牌生成留在事务外、限流之后，避免慢哈希占住连接和注册锁。限流口径不变：开关关闭时被拒绝的合法尝试同样消耗额度，额度耗尽优先返回 429。

## 备选与后果

不选浏览器长期localStorage token，避免将长期凭证暴露给前端脚本；也不首版兼容跨源Cookie的多套配置。密码算法已于 2026-10-28 定为 Argon2id（m=19456 KiB、t=2、p=1、16 字节 salt、32 字节 key，OWASP 最低推荐之一），会话期限定为 30 天滑动，限流定为每邮箱 10 分钟 5 次、每远端 IP 10 分钟 20 次；三者的本机实测耗时与运维参数调整须走明确的参数变更，不在请求路径动态调参。精确滑动过期意味着每次有效请求都写一次数据库，这是选定语义的成本，不用缓存或限频续期改变它。

应用层隔离便于保持业务日志与授权一致，但必须覆盖所有查询；未来若有数据库级隔离要求，再评估RLS或分库，改变代价高于调整前端部署。

验收：跨空间读写、凭证伪造、轮换重传、最后owner保护、一次性令牌并发消费、Cookie安全、非法Origin、空间切换慢响应。详见 [架构](../architecture.md)。
