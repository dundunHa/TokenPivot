## 1. 目标与非目标

目标：把认证、输入校验、稳定事件身份、逐项独立事务和持久化结果接成一条真实可用的批量采集路径。稳定身份固定为 `(workspace_id, source_id, source_event_id)`；规范化业务内容相同返回 duplicate，不同返回 conflict；超期先返回 expired；原始事件与分钟增量同事务成功提交后才返回 accepted。

非目标：不在 T-011 冻结采集格式、建设业务表/唯一索引、签发/轮换/撤销凭证、定义分钟聚合算法或实现清理重建；不改插件、不建查询 API/前端，不做事件覆盖修正。无 Redis、队列、异步接受、批次总事务、通用仓储/插件框架或新数据库依赖。无聚合写入的占位实现不得上线，也不得计作本任务完成。

## 4. 最简实现结构与请求流程

### 4.1 局部结构

拟新增 `internal/ingestion`：HTTP handler 解码/映射响应；service 负责逐项流程；postgres 存储实现负责参数化 SQL、事务和数据库错误转换。可先同包分文件，避免为一个端点创建多层目录。业务 service 不导入 pgx；只在消费方定义本用例需要的窄事务能力，postgres 文件用现有池实现。只需一条事务内工作路径，不建通用 UnitOfWork/注册系统，不引入 sqlc/ORM/mock 框架。

T-012 的事务内写入在 PostgreSQL 侧绑定到同一事务；不能从 service 调一个隐式开第二事务的聚合方法。若前置任务已有满足上述边界的类型，直接复用，禁止建立平行抽象。入口显式注入认证、存储和 handler；路由仅局部扩充已有 NewHandler 及调用者，不重构 server.Run。

### 4.2 顺序处理，不增加批内 goroutine

1. 插件凭证认证与整批外壳校验：限制 body、版本和条目数，拒绝无法安全解析的整体输入。凭证无效则整批无写入，不以 Cookie 回退。具体先后及响应按 T-007/T-010 冻结值，不在日志中记录 body/凭证。
2. 保留输入顺序与下标；相同 source_event_id 在同批可出现，不能只按 ID 组装结果导致覆盖。逐项校验格式、项目权限、数值/质量和时间；坏项独立报告，其余项继续。
3. 对可处理项使用独立事务。先满足身份/引用校验与发生时间有效性，再尝试事件插入；**过期判断必须发生在任何用于 duplicate/conflict 的业务身份查询之前**。
4. 插入首次成功：在同一事务调用 T-012 分钟增量；整个事务 Commit 确认成功后，才把该项写成 accepted。received_at 只写首次接收，重传不更新。
5. 插入身份已存在：读原规范化版本与内容比较，按 T-007 规则产生 duplicate/conflict；两种结果都不增加统计、不覆盖事件、不延长保留。
6. 单项错误回滚本项，不回滚此前已提交的项。完成后一次输出逐项结果；断连接/超时导致结果未达客户端时，客户端仍可按原身份重试。

请求级顺序处理减少事务/连接占用和结果顺序复杂度；其他请求可并发，以数据库唯一约束仲裁，不靠进程 mutex。没有吞吐数字承诺，不为未来性能预建并行模式。

## 5. 时间、规范化、事务与并发

### 5.1 时间与规范化责任

已定窗口是 `[T - 180*24h, T]`，两端包含；超出过去下界为 expired，未来不是 expired 而是对应永久校验拒绝。不把未来时间截成 T，不把接收时间替换发生时间。发生时间属于业务事实，修改它不是重试。

**T-007 冻结**：occurred_at 所指的请求最终完成时刻、解析与存储精度、允许时钟偏差、边界样例；规范化参与字段（发生时间/项目/模型/用量/质量等）、缺失与零值差异、JSON 表示差异、摘要及规范化版本。排除凭证、received_at、传输字段顺序。旧版本重传必须可按冻结规则与存量内容比较；不能仅用“当前版本哈希不同”判 conflict。不在本文发明双哈希升级框架。

建议时间依据由数据库提供并与后续清理共用，使用可测试的时间输入而非客户端时间；**精确采样点、精度及保留边界由 T-007 冻结，T-013 后续遵守并联测**。不得只采批次起点后在长等待中无限沿用：每项处理及冲突等待结束后、最终判断前需重新校验窗口。测试覆盖等待跨过下界、时间精度舍入及客户端不同偏移表示。received_at 是首次成功接受事务的接收时间，不声称数据库提供了精确 Commit 墙钟时间。

### 5.2 唯一竞争的拟采用路径

使用 Read Committed 和针对三字段唯一键的 `INSERT ... ON CONFLICT (...) DO NOTHING RETURNING ...`，不采用先查后插、也不使用 `DO UPDATE` 覆盖事实。[E1]

- INSERT 返回后，无论是否返回新行，先重新采样并复核窗口；已过期则回滚本项并返回 expired，不进入冲突 SELECT。
- 返回新行且仍有效：在同一事务写分钟增量；增量写入及其锁等待结束后、Commit 前再次复核窗口。已过期则连同明细回滚并返回 expired；仍有效才 Commit，确认成功后 accepted。
- 无返回行且仍有效：**另发下一条 SELECT**，在相同 workspace/source/event 身份下读取既存行及比较依据。不得把 INSERT 和读旧行塞进同一条 CTE 后假定必可见。[E1]
- SELECT 返回后（包括锁等待结束），先重新采样并复核窗口，再分有行或无行；已过期统一返回 expired。仍有效且有行时才比较内容：相同 duplicate，不同 conflict。需要维持读取至结果决定间的存在性时使用行共享锁，且与项目/凭证侧既定锁顺序一致。
- 仍有效但查询无行（例如竞争期间清理移走旧行）时，不是 duplicate，也不是 accepted；返回可重试的不确定结果，不用循环盲目重插。下一次重试必须重新通过时间判断。已能确认过期时，不用不确定结果代替 expired。
- 不把任意 `23505` 都转换为业务 conflict：只有本事件身份键触发的正常竞争走上述路径；其他唯一约束/SQL 错误是存储失败，安全记录、调查，不伪装成客户端改内容。
- 不提高到 Serializable，不加全局锁、不自动无限 SQL 重试；锁等待受请求/事务期限约束。死锁、连接故障或期限耗尽按可重试基础设施失败映射。

并发相同身份同内容只能一个首次插入并计数；失败事务释放后其他请求可以成为首次接受者。并发不同内容至多一个首次接受，其余在成功提交后比较为 conflict。不同事件更新同一分钟必须使用 T-012 的原子增量，不能读总数再写回。

### 5.3 保留竞争与原子性

根据[数据模型:60](<../data-model.md#L60>)，清理按首次 received_at，窗口按 occurred_at，两者需一致截点/精度。对合法事件 `occurred_at <= received_at`，正确清理的记录在清理截点时已不应属于可补报窗口；长事务沿用旧截点会破坏这个关系，因此不能只做批次起点检查。清理前后同一个过期事件必须都 expired，不根据是否还存行变化为 duplicate。

T-013 未完成不阻塞 T-011 编写受控竞争测试，但**不能据此宣称真实清理并发已验收**；未来清理上线须满足上述关系并重跑。不得以永久保留哈希、延长重传保留时间或把清理改为本任务来规避。

Commit 返回错误可能意味着结果不确定，而不一定回滚成功：绝不返回 accepted，也不声称“未写入”。客户端重传后由唯一身份解析为 duplicate 或新的 accepted。请求取消停止未开始项；已经提交项不撤销；进行中事务释放/回滚必须有界且归还连接，不用脱离请求的后台写入继续批次。

## 6. 认证与跨空间隔离

- workspace/source 只能来自 T-010 认证结果；请求中伪造字段无权改变它们。T-007 若允许这些字段，必须校验一致；若禁止则拒绝，不能静默采用攻击值。
- 凭证必须有效且关联的 source/workspace 一致。轮换后的新凭证仍命中原 source，合法重传保持 duplicate；撤销不删除明细或防重依据。
- 所有项目引用按 `(workspace_id, project_id)` 查；未归属允许为空不等于非法/跨空间项目可降为空。归档状态规则由前置任务冻结，不能临时把已归档项目重传改成另一个业务身份。
- 事件读取、插入和分钟写入均显式携带已认证 workspace；同 ID 跨空间互不去重、互不读写。source ID 同样不能由 payload 覆盖。
- 同一事务内完成需要一致性的引用/状态校验；涉及凭证撤销和项目状态竞争的锁顺序/授权时点复用前置约定，不凭无外键就省略授权。
- 本任务不实现浏览器成员权限，也不把浏览器 Cookie/Origin 机制混入插件端点；拒绝 Cookie-only 请求。
- 仅记录安全阶段、结果计数及脱敏错误分类；不输出 Authorization、Cookie、连接串、原始 SQL 错误/Detail、事件原文或完整配置。无需为本端点新建日志/指标平台。

## 7. 错误与部分成功语义

以下是语义要求，不是新增 HTTP 状态码或 JSON 字段；具体编码由 T-007 冻结。

| 情况 | 持久化/重试含义 |
|---|---|
| 整批认证失败、外壳不可解析、版本/体积/条数不合法 | 整批拒绝，无事件写入；不是逐项 accepted。 |
| accepted | 本项原始事件和分钟增量均已确认提交。 |
| duplicate | 同身份同规范化内容；没有任何新增用量，首次接收时间不变。 |
| conflict | 同身份不同内容，永久拒绝；不覆盖、不修正桶。 |
| expired | 先于查重的窗口拒绝；即使原记录仍在也不返回 duplicate/conflict。 |
| 单项格式/未来时间/项目越权/不支持最终用量 | 单项永久拒绝，不影响其他合法项；不泄露其他空间是否存在该 ID。 |
| 数据库/锁等待失败，Commit 结果不明 | 本项可重试或结果不确定，原 ID 重试；不能描述为已确认回滚。 |
| 客户端断连、请求取消、响应写失败 | 已提交事实不变；未收到结果的项按原 ID 重传。若还能响应，未处理项必须有明确可重试状态，不能凑满 accepted。 |

回滚明确成功和 Commit 不确定可共享“可安全按原 ID 重试”的客户端动作，但内部日志需可区分；不将整个批次失败误读成此前成功项被回滚。固定输入位置对应固定结果，即使同批多条 ID 相同。

## 8. 测试矩阵与验收命令

单测用合成凭证/事件与可控时间；认证真实行为、唯一竞争和分钟一致性必须用真实 PG，不能以 mock 证明事务原子性。测试中障碍用 channel/显式锁协调，不用 sleep 猜调度。

| 场景 | 必须断言 |
|---|---|
| 全新事件、混合好坏项、坏项首/中/末 | 每项对应输入位置；坏项不阻塞其他合法项；每个 accepted 的明细与分钟数一致。 |
| 同批重复、跨批重传、重复项首/中/末 | 恰一 accepted，其余 duplicate；原始行一条，所有分钟指标仅加一次，received_at 不续期。 |
| 相同 ID 改时间/项目/模型/用量/质量 | 在有效窗口内 conflict；原文和原桶不变，目标新桶无增量。 |
